## 1. Summary and verdict

The build does what the design's acceptance checks M-1 to M-9 ask for on the replay data. All 66 tests pass on JSON, Chroma and Qdrant, and the three stores return the same ids for every filter I tried. Namespace, `as_of`, feature and status filtering held under every odd input I tried. The checks are narrower than the design, though, and the evidence the author gives for the tests is weaker than it reads.

The three most important points:

1. **The tests do not protect the read-path rules in design sections 7.3, 7.4 and 7.6.** I mutated a throwaway copy of the code 25 ways and ran the JSON and extractor tests. 16 mutants survived (18 of 25 counting two that prove nothing: an equivalent change and a lock-age change that needs the hook tests). They include changed weights, recency set to 0 or inverted, importance ignored, the importance-3 reserve removed or opened to all records, sentence shortening disabled, the header left out of the token count, a 500 ceiling raised to 504, tie-breaking removed, `as_of` made exclusive, the path-escape check and the anchor check removed. The author's "tests checked for teeth" claim (`store-results.md` section 1) holds only for the cases they tried.
2. **The sync never removes or repairs stale records.** If a heading in a decision log is renamed, the old record stays `current`, is still injected, and its `source_path` anchor no longer exists. That breaks M-8 on live data. The renamed section's new record is discarded as a "duplicate" of the old one. The tests treat "kept, not deleted" as correct. The extractor can also invert status: a current section saying "not superseded" is stored as `superseded`. It can take a future date from the body as the record's timestamp.
3. **Cross-namespace isolation is complete for reads but not for writes.** Record ids are not namespaced. Writing the same id into another namespace overwrites the first record in all three stores. A query for the first namespace then loses that record. No test covers this.

Not built, and allowed by the design: hierarchical consolidation (7.7). No namespace has more than five records sharing a `source_task`, so the "only if the replay needs it" condition is not met. Not built, and not listed as a deviation in the design: the hook-driven write path for episodes (F-8).

Findings: 2 High, 7 Medium, 10 Low (section 4).
